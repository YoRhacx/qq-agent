## 写一篇新案例的模板

```markdown
# case-00N 一句话标题（症状，不是修法）

- **日期**：YYYY-MM-DD
- **影响**：谁受影响、坏了多久、怎么发现的
- **关联**：PITFALLS 编号、相关 guide

## 现场
（原始日志/端点输出，脱敏）

## 排查
（按证据推进的步骤；写"为什么排除了 X"）

## 根因
（机制层面，一句话能复述）

## 修复
（改了什么，为什么这样改）

## 验证
（真机证据，不是"测试通过"）

## 教训
（可迁移的规则，3 条以内）

## 遗留
（没解决的部分，或已知局限）
```

## 约定

- **脱敏**：QQ 号、群号、本机路径、令牌一律换成占位符（`1000000001` 这种主人的号也不写）。
- **别只写结论**：留下能复查的证据（命令 + 关键输出行）。
- **教训要可执行**：写"改 guard-check 检查 X"，不写"以后小心"。
