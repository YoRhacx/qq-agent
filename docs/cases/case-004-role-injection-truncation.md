# case-004 人格卡尾部三节凭空消失

- **日期**：2026-10-18
- **影响**：人格卡（`roles/小鲸鱼.md`，20371 字符）注入时被截到 18500，尾部「黑话规矩 / 指代命名 / 语癖」三节全丢——她"说话不对味"的直接原因之一。
- **关联**：[PITFALLS P-009](../../PITFALLS.md)

## 现场

控制台提示：「超出注入上限：当前模式实际注入 20370 字符，只有前 18500 字符会进入提示词」。

## 两道上限

| 限制 | 值 | 作用点 |
| --- | --- | --- |
| `role.maxInjectChars` | 默认 18500，代码硬顶 20000 | 注入前截断 |
| `ROLE_CONTENT_MAX_BYTES` | 64KB | 保存时报错 |

卡片 20371 字符 / 51289 字节：先撞第一道；若把上限抬到 25000，纯中文约 7 万字节又会撞第二道。

## 修复

1. 代码 clamp 20000 → **25000**（`src/bridge.js`），注释与校正日志同步；
2. 控制台 `input max=25000` 与前端校验；
3. 体积护栏 64KB → **128KB**；
4. 运行时 `POST /api/roles/limit {maxInjectChars: 25000}` 落盘，**不用重启**即生效；
5. 文档（`roles/README.md`、`RULES.md`）同步范围文案。

## 验证

`GET /api/roles/content?name=小鲸鱼` → `chars=20371 bytes=51289 limit=25000 truncated=false`，
警告清空；审计 46/49（3 个已知环境失败），与改前一致。

## 教训

1. **上限往往是复数的**：字符数、字节数、条数、时长，改一处要问"还有没有第二道"。
2. 硬顶和默认值要一起看：默认 18500 < 硬顶 20000，用户以为调了其实没调。
3. 运行时端点比改配置文件更安全——配置文件是主人手写的（P-009 的另一半）。
