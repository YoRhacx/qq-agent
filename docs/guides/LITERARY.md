# 文学性尺子：把「她写得有没有画面」变成可数的数

> 一句话：**练不了模型，就先有一把尺子；不然「改得更文学」只是感觉，改完也不知道是变好还是变坏。**
> 代码：[src/literary-score.js](../../src/literary-score.js)（零 import 的纯函数）、CLI [scripts/eval-literary.mjs](../../scripts/eval-literary.mjs)、基准 [scripts/fixtures/literary-eval.json](../../scripts/fixtures/literary-eval.json)。

## 一、为什么不是「拿大量文本去训练」

她的模型是托管服务（`deepseek-v4.1-flash` 之类），跑在别人的卡上：没有权重、没有训练接口，
本地能改的只有「每一次请求送进去的上下文」。所以「训练文学性」这个动作在这里不存在。

即便哪天能微调，「喂一大坨文本」也是最差的解法：模型学到的是**平均文风**（把好句子和凑字数的句子平均一遍），
人格、口癖、分条习惯会一起漂（灾难性遗忘），而且你无法回答「这次微调到底让哪几条变好了」。
真正有效的量级是**500~2000 条精选**，还要配评估集——那已经属于精细活了。

能立刻做的三层增强（本文件只负责第 3 层）：

| 层 | 做法 | 作用 | 状态 |
| --- | --- | --- | --- |
| 示范层 | 人格卡里放 15~30 组「对方说 X → 她回 A/B」对照 | 给模型具体的标尺，比形容词管用 | 已有（人格卡 §九 回复示例） |
| 检索层 | 小素材库按话题召回 2~3 条好句子进上下文 | 让「有画面」的写法随时可得 | 未做 |
| **评估层** | **把文学性拆成可数指标 + 40 条基准，改一次跑一次** | **让「改好了」可验证** | **本文件** |

## 二、五个指标与一类扣分

分数 0~100，越高越像人写的、越有画面。五项各自先算密度，再用 `sat(x, knee) = x/(x+knee)` 压到 0~1
（越往上越难加分，避免堆词就满分）。

| 指标 | 权重 | 在数什么 | 关键口径 |
| --- | --- | --- | --- |
| 具体性 `concreteness` | 0.30 | 能看见、能摸到、能数的名词占比 | 命中字数 ÷ 去标点字数，过 `sat(0.055)`；「大学」「火腿肠」「铃声」算，「生活」「意义」「成长」不算 |
| 画面 `imagery` | 0.22 | 明喻、量词数字、感官词 | (明喻×2 + 量词×1.5 + 感官×0.8)/百字，过 `sat(6)`；「像/好像/如同」算明喻，「仿佛/宛如」归 AI 腔 |
| 节奏 `rhythm` | 0.16 | 句子长短有没有起伏 | 0.55×理想句长占比（6~20 字最舒服）+ 0.45×句长变异系数 |
| 质感 `texture` | 0.12 | 标点是否单一、有没有重复、有没有憋气长句 | 标点种类 + 三字重复率 + 最长无标点段（16 字以内满分） |
| 人味 `voice` | 0.20 | 语气词、口语词、人称、问号叹号 | 按**句数**归一化后过 `sat(1.1)`——长文不该因为长而白拿分 |
| AI 腔扣分 `slop` | ×0.85 | 套话与含糊 | 标点密度 ×0.62 + 含糊词（很多/有点/其实/觉得…）×0.22 + 抽象密度 + 长句比 |

总分 = `Σ(权重 × 指标) × (1 − 0.85 × slop)`，落到分档：
`≥70 有画面 / ≥55 有味道 / ≥40 勉强 / ≥25 平 / <25 干瘪`。

> 「AI 腔」不只数「仿佛/不禁/一丝/一抹/涌上心头」，还数**正确的废话**：「重要的不是结果」「沿途的风景」
> 「愿你我都被温柔以待」「每一次相遇都有意义」。这类句子语法完美、信息为零，是最典型的 AI 味。

## 三、怎么用

```bash
npm run eval:literary                 # 跑 40 条基准（三条判据不过则退出码 1，可挂 CI）
npm run eval:literary -- --text "她把火腿肠掰成两半，一半塞给我"   # 单句打分 + 命中了哪些词
npm run eval:literary -- --file draft.txt      # 整段打分
npm run eval:literary -- --json                # 机器可读（接脚本/对比历史）
npm run eval:literary -- --set my.json         # 换一套基准
```

单句输出长这样（示意）：

```
总分 58.4  有味道
  具体性 0.71  画面 0.42  节奏 0.66  质感 0.55  人味 0.61  AI腔 0.08
  命中：火腿肠、铃声（具体）；像（明喻）；一次、三片（量词）
  短板：句长太齐（每句 8~10 字，读着像列表）
```

**看她自己现在多少分。** `--history` 直接从 `state/history/*.jsonl` 读她的出站消息打分（去掉图片/表情占位符、
6 字以下的反应句、以及编码坏掉的行）：

```bash
npm run eval:literary -- --history          # 最近 200 条
npm run eval:literary -- --history 500 --json
```

2026-10-29 实测（最近 400 条）：**均值 30.4 / 中位 28.6**，具体性 12、画面 17、节奏 65、质感 62、人味 27。
这个数字不是「她文学性差」，而是**聊天里她几乎不描述东西**——她的高分句全都带具体物件或动作
（「这破箱子转半天 里面装啥呢」58.8、「十一秒，一个女仆装的我站在锅前尖叫」58.4）。
按长度分组看（短 28.9 / 中 32.6 / 长 28.3）也说明问题不在句子长短，而在**有没有可用来说的东西**。

所以这把尺子的正确用法是：先看「她一天里写长句的机会有多少」，再看「那些长句做到了几分」。
想抬分，先抬**有画面的机会**（生活层笔记、看过的视频、群里的具体事），而不是往人格卡里塞形容词。

**基准是什么。** `scripts/fixtures/literary-eval.json` 里 40 条：`good` 16 条（有具体物件/画面）、
`flat` 12 条（通顺但空）、`slop` 12 条（套话/AI 腔）。当前校准值：

| 组 | 均值 | 最低 | 最高 |
| --- | --- | --- | --- |
| good | **61.6** | 54.9 | 74.x |
| flat | 27.7 | — | 46.4 |
| slop | 17.6 | — | 27.5 |

三条判据（`eval:literary` 与 `test:literary` 都检查）：`good > flat + 8`、`flat > slop + 8`、
`good 的下四分位 > slop 的上四分位`。**尺子自己失真时，任何「改好了」的结论都是假的**，所以校准跟指标一起钉进测试。

## 四、怎么用它改人格卡（改一次跑一次）

不要凭感觉改。流程是固定的三步：

1. **留底**：把改动前她最近 20~30 条真实发言抄成 `before.txt`（一行一条，空行分隔），跑 `--file` 记下分布。
2. **改卡**：一次只改一类东西（比如只加具体物件、只删套话），别同时动三样。
3. **对比**：同一条聊天记录让 DSH 用新卡重说一遍存成 `after.txt`，两边同一套指标对比。
   **只看「good 基准没有退步」不够**，要看她那批句子的均值有没有动、哪一项动了。

> 提醒：分条发的短句（「草」「行吧」）本来就不该高分——人味高、画面低是正常的。
> 尺子衡量的是「需要描述时她能不能写出画面」，不是「每句话都必须有画面」。评测时把纯反应句
> （少于 8 字、或只有语气词）剔掉，否则会拉低均值、吓到自己。

## 五、怎么加词、加基准

- **加词**：直接改 `src/literary-score.js` 顶部的词表（`CONCRETE` / `SENSE` / `ORAL` / `VAGUE` / `SLOP_MARKERS`），
  加完必须跑 `npm run test:literary`——它会重新验证 40 条基准还分得开。词表加宽容易，**加完不跑测试等于没加**。
- **加基准**：往 `literary-eval.json` 的 `items` 里加 `{ id, label, text, note }`，`label` 必须是
  `good` / `flat` / `slop` 之一；每组至少 10 条。加完跑 `npm run eval:literary` 看判据是否还过。
- **不要**为了让某一条过线去改权重——权重一改，之前所有历史分数都不可比。

## 六、已知局限（别拿它当文采认证）

1. 只看**可数特征**：它不知道「这句是否动人」，只知道「这句有没有具体东西、画面、起伏、口气」。
   把两句都写到 70 分，它分不出哪句更好——那是人的事。
2. **短句噪声大**：少于 12 字时密度类指标抖动明显，别拿单句下结论，看一批。
3. **中文标点**：全角/半角、省略号写法都会影响「质感」，比较时统一写法。
4. 词表是中文互联网语境的，写古诗/文言会误判（缺「之乎者也」这类词，且句长理想区间不适用）。
