# 星汐：把记忆画成星图（展示层）

> 一句话：**dsh-xingxi** 插件把我们攒下的「记忆卡 + 日记」画成一张星图，给主人看；它不参与她的提示词，不是第二套记忆。

## 1. 它是什么、不是什么

- 是：一个 DSH 插件（`dsh-xingxi@0.2.5`，装在 `C:\Users\testuser\.dsh\profiles\desktop\` 的 profile bundles 里），提供侧栏「星汐」面板、两个工具（`xingxi` 整本读、`xingxi_read` 按关键词/日期/文件读）和一个 `/xingxi` 斜杠指令。
- 星图怎么长：一颗星 = 记忆卡里的一条，或一篇日记；中间最亮的是记忆卡第一章第一条，八章各成一团星群，罕见的词之间连细线，越新越亮。
- **不是**：不是注入块，不写 `state/memory-brain.sqlite`，不进她的 system prompt。她的长期记忆仍走 memory-brain（五类记忆 + 衰减 + 检索），两边互不干扰。

## 2. 档案在哪

本机档案模式（不按会话绑文件夹——桥接会建/退会话，绑了就会散），两个路径写死在星汐自己的配置里：

- 配置：`C:\Users\testuser\.dsh\xingxi\config.json`
  ```json
  { "记忆卡": "D:\\qq-bot\\qq-bridge\\state\\xingxi\\记忆卡.md",
    "日记":   "D:\\qq-bot\\qq-bridge\\state\\xingxi\\日记" }
  ```
  只有 `记忆卡`（md 文件）和 `日记`（文件夹）两个字段被代码用到；**读配置是每次读盘，改完立即生效，不用重启 DSH**。
- 档案：`D:\qq-bot\qq-bridge\state\xingxi\`
  - `记忆卡.md` —— 八章（我是谁 / 长什么样 / 老大 / 群里的人 / 日常与约定 / 脾气和雷点 / 我怎么说话 / 我知道自己是什么），全部来自真实原话。
  - `日记\YYYY-MM-DD.md` —— 2026-10-11 ~ 10-29 共 13 天，一天一条 `- **MM-DD 周X**：…`。
  - `原始对话\YYYY-MM-DD.txt` —— 同 13 天的流水，`HH:MM [私聊|群] 说话人：正文`。**星图不读 .txt**（扫描只收 .md），这份是给人翻的底稿。

星数（2026-11-06）：记忆卡 **36 颗** + 日记 **13 颗** = **49 颗**，八章八种颜色。
用插件自己的解析器核过：`import { 解析一个文件 } from '.../dsh-xingxi/index.js'`，卡 36、日记每天 1。

### 两种格式的硬要求（写错会被静默忽略）

- **日记**：文件里必须有 `## YYYY-MM` 月份标题，条目必须是 `- **MM-DD 周X**：正文`。
  两条缺一条，这个文件就退化成「整篇一颗星」或直接没有星 —— 第一版我写成 `【2026-10-19】` 标题，13 篇全被当成普通 md，一颗日记星都没出来。
- **记忆卡**：章标题必须是 `## 一｜章名` 这种「汉字数字 + 分隔符 + 名字」（分隔符认 `、.．｜|·:：-—`），否则不会分配到那一章的颜色；章名下面写 `这一章讲什么：…` 的导语会被自动丢掉（不会变成一颗空星）；**第一章不拆条**（一整段自述），二~八章用 `- ` 分条，一条一颗星。

## 3. 为什么没跑「拾星」

拾星（把会话历史按天切、一天一批喂模型、产出当天日记与记忆卡条目）只能在 DSH 控制台面板里点，而且要按天调模型——我们这份历史 13 天，跑一遍就是 13 次调用。

所以走的是另一条路：`scripts/build-xingxi-archive.mjs` 直接读 `state/history/*.jsonl`（私聊 1262 行 + 群 421 行），一次生成日记与原始对话，**零模型成本**；记忆卡是手写的（脚本不碰它，重跑只重写 `日记/` 与 `原始对话/`）。

```bash
cd D:\qq-bot\qq-bridge
ELECTRON_RUN_AS_NODE=1 'D:\dsh\DeepSeek Harness.exe' scripts/build-xingxi-archive.mjs
```

以后想让拾星接管：面板里点「拾星」，它会按 `日记` 里的日期接上（已整理到哪天记在 `.xingxi.json`），不会重复劳动。

## 4. 为什么她的会话里调不到 `xingxi_read`

`plugins/qq-agent-presets/qq-tool-restrict.mjs` 的执行期白名单只放行两样：`SAFE_EXACT`（`qq_*` 一族 + `todo_write` / `ask_user_question`）和三个 MCP 前缀（`mcp__snowluma__` / `mcp__snowluma-host__` / `mcp__web-search-safe__`）。`xingxi_read` 不在里面 ⇒ 默认拒绝。

**这是故意的**：星图是给人看的展示层。真要让她翻档案，等于把「记忆主库」从 memory-brain 换成 md 文件，两套同时当主记忆会打架（同一件事两处记、一处改了另一处不知道），而且每次唤醒多一次工具调用。

哪天真要开，三件事按顺序做：① 把记忆卡里偏后台的段落（花销、缓存、工具名）收拾干净——她的硬规矩是不许对外说这些；② `SAFE_EXACT` 加 `xingxi_read`（只读，不给 `xingxi`）；③ preset 里加一句「想不起旧事就 `xingxi_read` 翻档案，别猜、别编」并重建 `plugins/qq-agent-presets/presets/qq-chat-v2.patch.yml`。

## 5. 日常维护

- 加一条记忆：直接编辑 `记忆卡.md` 对应章节，写成 `- 一条事实`（写事实不写口号），刷新星图即可见。
- 写今天的日记：`日记\YYYY-MM-DD.md`，格式 `【YYYY-MM-DD】` + 空行 + `- **MM-DD 周X**：…`。
- 星图空白 / 星很少：先看 `~/.dsh/xingxi/config.json` 两个路径是否还在、`记忆卡.md` 文件名里有没有「记忆卡」二字（插件靠文件名认它）。
